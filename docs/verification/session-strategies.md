# 多个 AI 对话怎么同时开：验收说明

## 30 秒看懂

### 这一步改了什么？

以前，Roadmap 不管你用 Codex、Claude Code，还是几个对话共用一个项目，都给出差不多的 Git 指令。现在它会先认清你是哪种情况，再告诉你该怎么开多个开发对话。

### 你只看哪里？

只看下面三个“你会怎么操作”的例子：

1. Codex 怎么开；
2. Claude Code 怎么开；
3. 几个对话共用同一个项目文件夹时怎么开。

### 看到什么算通过？

- 每个例子都直接告诉你“新建什么、把哪段提示词发过去”，不用你自己想 Git 命令。
- 共用同一个文件夹时，明确写着“大家先别保存版本，最后只让一个整合对话收口”。

### 哪些内容可以不看？

后面的英文名字、共同版本编号、失败恢复和清理细节都是给开发 AI 执行的。你不需要记，也不需要操作。

---

## 例子一：你在 Codex 里开发

假设 Roadmap 写着：2A 做页面，2B 做数据读取，而且两边不改同一批文件。

你会看到这样的引导：

> 从刚刚通过验收的版本，新建两个 Worktree 任务。  
> 把 2A 的提示词发给第一个，把 2B 的提示词发给第二个。

你只需要新建两个任务并粘贴提示词。每个任务拿到自己的项目副本，不会直接覆盖另一个任务的文件。

每个任务开始时，AI 会自己确认：“我拿到的是不是刚刚通过的那个版本？”如果不是，它会停下来告诉你，不会在旧版本上继续做。

两边都做完以后：

1. 你分别看结果；
2. 通过的那边才保存版本；
3. 最后新建一个整合任务，把两个通过的结果放回一起。

## 例子二：你在 Claude Code 里开发

如果你用 Claude Desktop：

> 新建两个 Code Session，把 2A、2B 的提示词分别发过去。

如果你用 Claude Code 命令行：

> 分别用两个不同名字开启 Worktree Session，再粘贴 2A、2B 的提示词。

这里有一个 AI 会替你注意的坑：Claude 新开的副本有时来自网上的默认版本，而不是你本机刚刚验收通过的版本。Roadmap 会要求它先核对共同起点；版本不对就停止，不会假装已经拿到了最新结果。

退出 Claude Session 时，如果里面还有尚未整合的改动，必须先保留。等整合完成以后，才能归档或删除临时副本。

## 例子三：几个对话共用同一个项目文件夹

有些时候，新开的几个 AI 对话其实都在操作同一份文件。这种情况不能让它们各自切换分支或保存版本，否则很容易把别人的半成品一起带进去。

Roadmap 会这样写：

> 新建三个普通 Session，分别粘贴 3A、3B、3C 的提示词。  
> 三个 Session 只能改各自列出的文件，期间都不切分支、不暂存、不提交。  
> 三边都通过以后，只让一个整合 Session 检查并统一提交。

只要某个 Session 发现“我必须改别人负责的文件”，它就要停下来报告，不能继续抢着改。

这也是本轮最重要的一句话：

> **并行的人可以有多个，最后收口的人只能有一个。**

## 工具没有自动给项目副本怎么办？

Roadmap 还可以要求开发 AI 手动创建 Worktree。你仍然只负责粘贴提示词，命令由 AI 执行。

如果创建失败，AI 必须停下来，不能偷偷改成“大家共用一个文件夹再来回切分支”。因为那不是同一种安全方式。

## 什么时候不允许并行？

下面任一件事说不清楚，就改为一个 Session 按顺序做：

- 不知道几个 Session 是不是共用同一个文件夹；
- 不知道大家是不是从同一个已通过版本开始；
- 两个步骤需要修改同一个文件；
- 没有最后负责收口的整合步骤。

变慢一点，比几个 AI 相互覆盖更容易挽回。

## 给维护者看的完整检查结果

下面内容用于后续自动测试和维护，用户验收时可以跳过。

| 场景 | 选择结果 | 开始前 | 并行期间 | 验收后 | 清理 |
|---|---|---|---|---|---|
| Codex 独立任务 | `codex-managed-worktree` | 核对共同版本 | 每个任务只改自己的文件 | 通过后提交给整合任务 | 整合且无未保存内容后归档 |
| Claude Code Worktree | `claude-managed-worktree` | 核对本地共同版本 | CLI 或 Desktop 独立目录 | 通过后提交，待整合内容要保留 | 整合后归档或移除 |
| AI 手动建 Worktree | `manual-worktree` | Git、目录和共同版本可用 | 每个 Worktree 独立分支 | 通过后提交 | 确认无未提交文件后移除 |
| 共用项目目录 | `shared-directory` | 文件范围完全不重叠 | 不切分支、不暂存、不提交 | 只标记可整合 | 唯一整合 Session 统一提交 |

完整机器可读案例位于 `tests/golden/session-strategies.json`。OpenCode 仍不在 V1 支持范围内，不会套用 Codex 或 Claude Code 的流程冒充兼容。
