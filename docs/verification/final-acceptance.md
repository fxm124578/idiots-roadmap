# 三项基础能力最终验收

## 30 秒看懂

### 这次最终改好了什么？

Idiots Roadmap 现在守住三件事：

1. Roadmap 写错了，AI 也不能稀里糊涂离开 Plan。
2. 用户换了能力或修改计划，已经做完的步骤不会被重写，旧窗口也不能覆盖新计划。
3. Codex、Claude Code 和共用项目文件夹不再使用同一套并行办法。

### 你只看哪里？

只看下面的“修复前 / 修复后”和“三种完整走法”。

### 看到什么算通过？

- 三个问题都有明确的修复后结果，而且失败时会停下来保护现有内容。
- Codex、Claude Code、共用文件夹都能从“开多个开发对话”走到“一个整合对话收口”。

### 哪些内容可以不看？

最后的测试数量、英文名字和保存方式都是给开发 AI 追查问题用的。你不用看代码、终端、日志或测试报告。

## 问题一：Roadmap 出错时会不会乱跑？

### 修复前

AI 第一次写错后会尝试修正；如果再次写错，系统可能只停止纠错，没有把“仍然留在 Plan”说清楚。

### 修复后

- 尝试退出 Plan 时，只要 Roadmap 还有问题，每一次都会被拦住。
- 普通结束回答时，第一次错误让 AI 修正一次；第二次不再无限重写，但旧 Roadmap 保持不变，并明确告诉用户仍在 Plan。
- 系统不知道当前模式、事件或 Session 时不会猜，也不会写文件。

一句话：**可以停止反复纠错，但不能拿坏 Roadmap 冒充成功。**

## 问题二：改计划会不会把做完的事弄丢？

### 修复前

步骤身份依赖“它排在第几步”。插入、删除或重新排序后，系统容易把“显示编号变化”和“换了一个步骤”混在一起；两个旧窗口也缺少明确的先后保护。

### 修复后

- 每个步骤有不会跟着排序变化的身份。
- 已经通过的步骤保留原内容和当时的能力范围；切换成“完全不看代码”只重写未完成步骤。
- 每次更新都有新版本。旧窗口拿旧计划回来保存时，会被要求重新读取，不能覆盖较新的计划。
- 旧版 Roadmap 第一次更新时会安全升级；失败就保留旧文件。

一句话：**已经盖章通过的内容锁住不动，未来步骤才跟着新选择变化。**

## 问题三：多个开发对话会不会互相踩文件？

### 修复前

Roadmap 虽然会标并行，但“独立项目副本”和“几个对话共用同一个文件夹”混用了相似的分支指令，容易让用户以为它们是同一种情况。

### 修复后

- Codex 有独立项目副本时，每个任务先核对共同起点，再只改自己的文件。
- Claude Code 使用自己的 Worktree Session；如果新 Session 没拿到刚通过的本地版本，会停下来，不在旧版本上开发。
- 工具不自动隔离时，开发 AI 可以手动建立独立副本，用户不用操作 Git。
- 多个 Session 共用同一个文件夹时，所有并行 Session 都不切分支、不暂存、不提交；即使用户验收通过，也只把结果留给唯一整合 Session。
- Skill 发现共同起点或文件范围说不清楚时，会改为串行，不假装可以并行。

一句话：**并行的人可以有多个，最后收口的人只能有一个。**

## 三种完整走法

### Codex

```text
先完成并验收共同规则
        ↓
从这个已通过版本新建多个 Worktree 任务
        ↓
每个任务只做自己的步骤
        ↓
用户分别验收，通过后各自保存结果
        ↓
新建唯一整合任务，合并并复验
```

任何任务发现自己不是从共同版本开始，立即停止。

### Claude Code

```text
先完成并验收共同规则
        ↓
CLI 使用不同 Worktree 名称，或 Desktop 新建多个 Code Session
        ↓
每个 Session 核对是否包含刚通过的本地版本
        ↓
用户分别验收，通过后保留并保存结果
        ↓
唯一整合 Session 合并并复验
```

退出 Session 时还有待整合内容，就先保留，不能直接删除。

### 多个 Session 共用同一个项目文件夹

```text
先完成并验收共同规则
        ↓
新建多个普通 Session，分别粘贴提示词
        ↓
各自只改互不重叠的文件
        ↓
所有 Session 都不切分支、不暂存、不提交
        ↓
用户分别验收
        ↓
唯一整合 Session 检查全部改动并统一提交
```

只要出现文件重叠、意外提交或必须修改公共文件，整个并行批次就停止，不能互相覆盖。

- V2 使用稳定 Roadmap 身份、版本号、共同起点和步骤状态摘要。

- 共用目录的并行提示词必须明确：不切分支、不暂存、不提交，验收通过后仍不提交。
