# 计划更新验收说明

## 30 秒看懂

这一步解决的是：**计划改了，不等于已经做完的东西要重来。**

你只需要看下面两个例子：

1. 小明原来选“能看 Python”，做完了第 1 步；后来改成“完全不看代码”。结果应当是：第 1 步原样保留，只有后面的步骤改成大白话验收。
2. 小明同时开了两个开发窗口。新窗口先更新了计划，旧窗口随后也想保存。结果应当是：旧窗口被拦住，刚保存的新计划没有被盖掉。

看到这两个结果，就算本步通过。后面的“系统怎么做到”是留给开发 AI 查问题的，你可以不看。

## 例子一：换了能力，做完的事不会消失

### 原来的情况

- 用户选择了“能看 Python 基础代码”。
- 第 1 步已经通过验收，内容是“完成导入功能”。
- 第 2、3 步还没做。

### 用户改变选择

用户改成“完全不看代码”。

### 现在会发生什么

- 第 1 步仍然显示“已完成”，原来的说明和验收记录全部保留。
- 第 2、3 步会重新写成不用看代码也能验收的版本。
- 如果 AI 试图把第 1 步改回“未完成”、删掉它或偷偷换掉内容，更新会被拒绝。
- 中间需要插入新步骤时，新步骤有自己的身份；页面上的“第几步”可以重新排列，不会把不同步骤认成同一个。

一句话理解：**已经盖章通过的内容锁住不动，能力变化只影响未来。**

## 例子二：旧窗口不能盖掉新计划

### 原来的情况

两个开发窗口都打开了同一份第 1 版计划。

### 接着发生

- 新窗口先保存，计划变成第 2 版。
- 旧窗口不知道这件事，还拿着第 1 版继续保存。

### 现在会发生什么

- 旧窗口会收到“计划已经更新，请重新读取”的提示。
- 第 2 版计划保持不变。
- 旧窗口必须先看最新计划，才能继续改。

一句话理解：**后保存的不一定赢，基于旧计划的窗口没有覆盖权。**

## 人工验收清单（2 项）

- [ ] 阅读“例子一”，确认已完成步骤保持原样，只有未完成步骤跟随新能力变化。
- [ ] 阅读“例子二”，确认旧窗口会被拦住，最新计划不会被覆盖。

## 给开发 AI 的核对信息

以下内容不是用户验收要求。

- 每份新计划都有稳定的 `roadmapId`。
- 每次成功更新都会增加 `revision`；更新必须带上它看到的 `baseRevision`。
- 步骤内部 `id` 不再由当前位置决定；`label` 和 `displayOrder` 只负责用户看到的顺序。
- `.idiotsroadmap/state.json` 记录当前版本、内容指纹、用过的步骤 ID 和步骤状态摘要。
- 删除后的步骤 ID 不能再次使用。
- V1 文件仍可读取；首次成功的 V2 更新会同时生成新版本信息和状态记录。
- 迁移、版本检查或合并失败时，原文件不变，并进入可重新读取后恢复的状态。

覆盖场景：

- 能力切换后保留已完成步骤；
- 在现有步骤之间插入新步骤；
- 删除未完成步骤并阻止 ID 复用；
- 拒绝旧版本窗口覆盖；
- 拒绝已完成状态回退；
- V1 首次更新迁移到 V2。
