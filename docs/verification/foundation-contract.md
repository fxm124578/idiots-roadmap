# 三项基础修复：30 秒看懂

## 这一步改了什么

这一阶段还没有开始修程序，只是先把三支开发队伍必须共同遵守的规则说清楚。

同时，这条规则已经写进 Idiots Roadmap Skill 本身：

> 以后只要用户选择“完全不看代码”，Roadmap 就必须要求验收文件先给一段“30 秒看懂”，不能只在当前项目里临时这样写。

这样做是为了避免：

> 三个 AI 同时开工，最后却发现每个人理解的“修好”都不一样。

## 你只需要看什么

只看下面“三件事”和“多个 AI 怎么合作”两部分。

看到它们和你想解决的问题一致，这一步就算通过。后面的技术约定是留给开发 AI 用的，你不用看懂。

## 三件最重要的事

### 1. 出错也不能乱跑

以前的风险是：

> Roadmap 连续生成失败后，AI 可能还是继续离开计划阶段。

修好后必须是：

> Roadmap 没生成成功，AI 就留在计划阶段；旧文件也不能被弄坏。

### 2. 改计划不能弄丢已经完成的进度

例如你原来能看一点代码，后来改成“完全不看代码”。

修好后必须是：

- 已经完成的步骤原样保留；
- 只重写还没完成的步骤；
- 旧的 AI 对话不能用过期计划覆盖新计划。

### 3. 多个 AI 不能互相踩文件

不是所有“同时开发”都一样。

Codex、Claude Code 和多个 AI 共用同一项目文件夹时，必须采用不同的合作方式，不能套用同一组 Git 指令。

## 多个 AI 怎么合作

### 在 Codex 里

给每个并行任务开一个独立的 Worktree 任务。

你可以把 Worktree 理解成：

> 每个 AI 都拿到一份互不干扰的项目副本。

每个 AI 只做自己的部分；你验收通过后，最后再统一合并。

### 在 Claude Code 里

使用 Claude Code 自己提供的 Worktree 或隔离 Session。

开始前先确认它们拿到的是同一个已通过版本，避免一个 AI 从新版本开始、另一个 AI 从旧版本开始。

### 工具没有自动隔离时

由开发 AI 手动准备独立 Worktree。Git 命令仍由 AI 处理，不要求你操作。

如果准备失败，就停止并告诉你原因，不能偷偷改成不安全的做法。

### 多个 AI 共用同一文件夹时

这种情况下仍可同时修改互不重叠的文件，但有三条硬规则：

- 不切换分支；
- 不各自保存版本；
- 不修改其他 AI 负责的文件。

所有 AI 完成并经过你验收后，再由一个专门的整合 AI 统一检查和保存。

## 每一批怎么结束

同一批并行任务全部通过后，下一批只能做一件事：

> 把这一批结果放到一起，确认没有互相打架。

不能跳过整合，也不能用一个模糊的“最后再看看”同时承包好几批工作。

## 出问题时怎么办

任何 AI 遇到下面情况都必须停止：

- 需要修改其他 AI 的文件；
- 拿到的项目版本不是共同起点；
- Worktree 或分支已经被占用；
- 项目中突然出现不属于本步骤的新改动；
- Roadmap 已经被另一个 Session 更新。

停止后只说明发生了什么和下一步怎么处理，不允许靠删除、覆盖或强制上传绕过去。

## 给开发 AI 的技术约定

下面是实现时必须遵守的精简索引，用户验收不需要阅读：

- Roadmap 使用 `roadmapId + revision + baseRevision` 防止过期覆盖。
- 步骤内部 ID 稳定，用户可见编号独立。
- 已完成步骤保留创建时能力范围，新能力只约束未完成步骤。
- V1 可读取，首次 V2 更新原子迁移，失败时保留旧文件。
- 任何无效 `ExitPlanMode` 都拒绝；Stop 只自动纠错一次。
- 并行流程明确 `workspaceStrategy` 和共同 `baseCommit`。
- 并行批次后紧接唯一串行整合批次。
- 完整字段和迁移规则以 `skills/idiots-roadmap/references/roadmap-protocol.md` 的“V2 修复契约”为准。
