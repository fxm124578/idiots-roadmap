# Idiots Roadmap

把技术计划改写成面向用户的执行 Roadmap。强调步骤边界和用户可验收结果，不追求把技术实现展开到最细。

## 严守边界

- 只在宿主处于 Plan 模式时运行。无法确认是 Plan 模式时，说明限制并停止。
- 只生成 Roadmap，不批准计划、不退出 Plan、不实现功能、不监听后续反馈。
- 不调用外部 API、额外模型或网络服务。
- 完成 Roadmap 正文或内部标记后立即停止。

## 执行流程

1. 检查当前对话是否已完成本计划的两轮选择。已完成则复用，不重复询问。
2. 对每个新计划目标先询问：
   - `启用 Idiots Roadmap`
   - `本轮不启用`
3. 用户不启用时，在最终计划末尾加入 `<!-- IDIOTS_ROADMAP:OPTOUT -->`，不要生成 Roadmap。
4. 用户启用后再询问能力范围：
   - 始终提供 `完全不看代码`。
   - 根据 hook 提供的仓库语言，最多提供两个 `能看……基础代码` 选项。
   - 保留宿主原生“其他”入口，让用户自由描述能力。
5. 若已有 Roadmap，在第二轮问题中原样显示警告：`选择与当前不同的能力范围，会重写全部未完成步骤；已完成步骤保持不变。`
6. 之后继续完成正常的产品和实现澄清，再生成技术计划与 Roadmap。

优先使用 Codex 的原生 Plan 问题组件或 Claude Code 的 `AskUserQuestion`。不可用时才用纯文本逐轮提问。不要把两轮问题合并。

生成前只读检查仓库：

- 是否为 Git 仓库、当前分支、工作区是 `clean`、`dirty` 还是 `unknown`；
- `git remote` 是否存在，以及是否指向 GitHub；只展示 remote 名称和已脱敏的仓库标识，不显示 URL 中的凭据；
- 检查失败时记录 `unknown`，不要为了探测状态修改仓库或联网。

## 拆分步骤

- 用 128k 上下文作保守估算：预留约 30% 给系统、仓库和工具输出；剩余容量按一次开发约 40%、三轮反馈各约 20%控制每步规模。
- 每步只产生一个连贯、可运行、可单独反馈的结果。
- 遇到跨多个子系统、迁移与功能混杂、或多个独立验收目标时继续拆分。
- 每步提示词必须要求开发 AI：
  - 只实现当前步骤；
  - 运行必要技术检查；
  - 完成后停止并等待用户验收；
  - 只有用户明确通过后才把步骤标为完成。
- 技术检查写进开发提示词，不算用户验收。
- 每步用户验收必须为 1–2 项。

## 安排并行 Session

- Roadmap 面向多个开发 Session 同时操作项目，不把“并行”简化成多个步骤一起开始。
- 先确定共享契约，再根据文件所有权划分步骤；只有允许修改的文件或目录互不重叠时，才能把步骤放进同一并行批次。
- 路由、数据库结构、全局配置、依赖锁文件、权限安全、共享状态和公共设计系统默认串行。若确实需要并行，先用一个串行步骤确定契约和文件归属。
- 同一并行批次最多安排 3 个 Session。无法明确文件范围或冲突风险时，宁可标为串行。
- 每个并行批次后必须有一个串行 `integration` 步骤；它依赖该批全部步骤，只负责合并、联调和用户可见的整体复验。
- 每步都声明：
  - 所属开发批次；
  - `serial` 或 `parallel`；
  - 必须先通过的步骤；
  - 当前 Session 唯一允许修改的文件或目录范围。
- 并行步骤的提示词要求开发 AI：只修改声明范围；发现需要跨范围修改或与其他 Session 冲突时立即停止并报告；宿主支持独立 worktree 时优先使用，共享工作目录时不得切换分支、暂存或提交，由后续整合 Session 统一收口。
- 整合步骤的提示词必须说明：确认全部前置 Session 已通过；共享目录直接联调现有改动，独立 worktree 则合并各 Session 已确认的提交；只处理冲突、联调和回归，不顺手扩需求。
- 分支和 worktree 是开发 AI 的隔离手段，不要求用户执行 Git 命令；本 Skill 不创建 Session、分支或 worktree，也不合并代码。

## 安排 Git 与 GitHub

- Roadmap 固定显示当前本地 Git、工作区、远程仓库、整合分支、提交时机和推送时机。
- 未初始化 Git 时，把初始化和基线保护折叠进第一个开发步骤；完全不看代码且有前端时，该步骤仍必须交付可见前端结果，不单列技术准备步骤。
- 工作区为 `dirty` 或 `unknown` 且计划包含并行批次时，在首个并行批次前安排串行 `prepare-baseline`。提示开发 AI 先展示检测结果并请求用户决定如何保护现有改动；不得自行 stash、提交、覆盖或清理。
- 整个 Roadmap 使用一个稳定整合分支，如 `ir/<goal-slug>`：
  - 当前不在整合分支时，第一个步骤从干净基线创建它；已有改动时先保护基线，未初始化 Git 时在第一步初始化并建立整合分支；
  - 后续串行步骤继续使用整合分支；
  - 每个并行步骤在开始开发时才从已通过的整合基线新建唯一分支/worktree，如 `ir/<goal-slug>/<step-id>`；
  - 并行步骤全部验收通过后，串行整合步骤把这些分支合回整合分支。
- 开发完成时先停止等待验收。只有用户回复当前步骤通过后，开发 AI 才能提交当前步骤声明范围内的文件。
- GitHub remote 未连接时明确写“未连接（不影响本地并行）”，不自动创建远程仓库、登录或添加 remote。
- 并行子分支一律不推送。只有存在远程仓库、Roadmap 最后一个串行步骤通过验收且用户再次明确同意后，才允许推送整合分支。
- Git 操作失败、基线变化或出现范围外改动时，开发 AI 必须停止并说明下一步，不得用 reset、checkout、clean、强制推送等破坏性命令绕过。

## 适配用户能力

### 完全不看代码

- 只用页面操作、视觉表现、样例输入输出、截图、可打开报告或其他可理解证据验收。
- 不要求用户查看代码、diff、终端、日志或测试报告。
- Roadmap 中凡是要求开发 AI 交付 README、报告或其他验收文件，提示词都必须要求该文件先提供“30 秒看懂”的口语化入口，再提供技术细节。
- “30 秒看懂”固定回答：本步改了什么、用户只看哪里、看到什么算通过、哪些技术内容可以不看。
- 用户验收清单只引用这段口语化入口能直接看懂的结果；不得把“文件存在”“测试通过”或一串技术字段本身当作用户验收。
- 即使原文件面向开发者，也要在最前面新增独立的小白验收入口，不能让用户先穿过技术说明才能找到结论。
- 仓库有前端时，把首个相关开发步骤安排成可打开、可点击、可反馈的页面或核心流程。
- 把必要环境准备折叠进首个前端步骤，不单列数据库、后端重构或基础设施步骤。
- 后端未完成时，可先按明确数据契约使用清楚标注的演示数据；随后必须有真实集成步骤，并再次通过同一前端流程验收。
- 不得把未实现的支付、权限、安全或数据写入表现为已完成。
- 没有前端时，优先提供样例输入输出、可打开报告或可视化证据。

### 能看代码或自定义能力

- 只在用户明确选择的语言中使用代码或 diff 验收。
- 其他语言仍按完全不看代码处理。
- 只要求阅读，不要求用户亲自修改代码。
- 严格遵守自定义描述，不推断或扩大能力。
- 不强制前端优先，按风险和依赖顺序安排。

## 输出协议

生成前完整读取 [references/roadmap-protocol.md](references/roadmap-protocol.md)。严格使用其中的稳定 HTML 标记；用户可见标题和正文跟随当前对话语言。

- 每个子步骤固定使用这些标题图标：`🧩` 子步骤、`📋` 第 1 步提示词、`🎯` 要求、`⚠️` 约束、`🚧` 边界条件、`✅` 验收标准、`☑️` 第 2 步人工清单、`💬` 第 3 步回复。
- 每个子步骤标题后必须用单行标明 `➡️ 串行 Session` 或 `🔀 并行 Session`，并显示批次、前置步骤和允许修改的文件范围。
- 紧接着用 `🌿 Git` 或 `🔗 Git` 单行说明：本步是否新建/合并分支、目标分支、验收后提交，以及是否允许推送。
- Roadmap 在开发步骤前提供简短的 `Session 安排`：同一批次中标为并行的子步骤可分别在多个 Session 同时执行，下一批必须等待其依赖全部通过。
- Roadmap 在 Session 安排前提供 `Git 状态`，说明是否连接 GitHub；未连接不自动补连。
- 完全不看代码模式下，每步提示词必须明确生成或更新口语化验收入口；验收清单必须检查用户能否看懂结果，不检查代码和技术测试。
- 第 1 步的单个代码块包含实现要求、约束、边界条件和 1–2 项验收标准。
- 第 2 步把同样的 1–2 项验收标准改成可勾选清单，不增加新验收项。
- 第 3 步提供包含当前子步骤标签的精确回复，例如：`4-3b 通过，请继续。`
- 新目标使用 `action: "new"`。
- 同一目标更新或能力切换使用 `action: "update"`，复制全部已完成步骤及其稳定 ID。
- 已完成步骤必须原样保留；只重写未完成步骤。
- 最终回答包含一份技术计划和一个完整 Roadmap 标记块。
- 不在标记块之外重复 Roadmap 正文。

hook 正常时会校验并写入项目根目录的 `IDIOTS_ROADMAP.md`。缺少 Node.js 或 hook 未启用时，仍输出完整标记块，供用户手动保存；不要因此尝试在 Build 模式继续工作。
